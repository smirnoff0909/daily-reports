# Ежедневные отчёты

Внутреннее приложение: инженеры каждый день записывают, что делали и сколько часов на это ушло, руководитель смотрит месяц и выгружает его в Excel.

Рассчитано на команду до нескольких десятков человек. Один процесс приложения, одна база, никаких очередей и внешних сервисов.

## Из чего собрано

- FastAPI, серверные шаблоны Jinja2, немного обычного JavaScript — сборки фронтенда нет
- PostgreSQL, миграции через Alembic
- Сессия в подписанной cookie, пароли в argon2
- Caddy как обратный прокси с автоматическим сертификатом
- Всё поднимается через Docker Compose

## Модель данных

`users` — сотрудники и роли (`engineer`, `manager`).
`reports` — шапка на день, уникальная пара «сотрудник + дата».
`report_items` — строки отчёта: название задачи и фактические часы.
`audit_log` — кто и когда создал или изменил отчёт.

Сотрудники не удаляются, а отключаются через `is_active`, иначе разъедутся прошлые отчёты.

## Запуск

```bash
cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"   # в SECRET_KEY
# заполните POSTGRES_PASSWORD и SITE_ADDRESS
docker compose up -d --build
```

Миграции применяются при старте контейнера. Дальше заведите людей:

```bash
docker compose exec app python -m scripts.manage_users add \
  --name "Иванов Иван Иванович" --login ivanov --role engineer
docker compose exec app python -m scripts.manage_users add \
  --name "Петров Пётр Петрович" --login petrov --role manager
```

Пароль спрашивается интерактивно и не остаётся в истории команд. Другие команды: `passwd`, `disable`, `enable`, `list`.

Если сайт работает по `http` без сертификата, поставьте `COOKIE_SECURE=false` — иначе браузер не сохранит cookie и вход не сработает.

## Разработка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
export DATABASE_URL="sqlite+pysqlite:///./dev.db" SECRET_KEY=dev COOKIE_SECURE=false
pytest -q
uvicorn app.main:app --reload
```

Тесты гоняются на SQLite и не требуют поднятой Postgres. Боевая база — только Postgres.

## Страницы

| Адрес | Кто видит | Что делает |
| --- | --- | --- |
| `/login` | все | вход по логину и паролю |
| `/reports/new?date=` | сотрудник | форма за день, итог по часам считается на лету |
| `/reports/my?month=` | сотрудник | свой месяц, пропущенные рабочие дни подсвечены |
| `/reports?month=&user_id=` | руководитель | все отчёты за месяц, фильтр по сотруднику |
| `/reports/export.xlsx` | руководитель | выгрузка того же среза в Excel |
| `/reports/{id}` | владелец и руководитель | детализация дня и история правок |

## Правила, зашитые в логику

- Один отчёт на сотрудника в день, внутри — произвольное число задач.
- Свой отчёт правится `EDIT_WINDOW_DAYS` дней (по умолчанию три), дальше только руководителем. Каждое изменение пишется в `audit_log`.
- Часы: больше нуля и не больше 24 на задачу, не больше 24 за день. Свыше 12 часов интерфейс подсвечивает итог, но сохранить разрешает.
- Будущие даты закрыты для ввода.
- «Сегодня» считается по `APP_TIMEZONE`, дата хранится как `date` без времени.

## Резервные копии

`scripts/backup.sh` делает `pg_dump`, жмёт его и удаляет копии старше 30 дней. В cron:

```
0 2 * * * cd /opt/daily-reports && ./scripts/backup.sh >> /var/log/daily-reports-backup.log 2>&1
```

Копии обязательно уносите за пределы этого сервера — иначе они умрут вместе с диском.
