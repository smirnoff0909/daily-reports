# Развёртывание

Памятка для системного администратора. Приложение внутреннее: инженеры
ежедневно записывают задачи и часы, руководитель смотрит месяц и выгружает Excel.
Команда — до нескольких десятков человек, нагрузка минимальная.

## Что нужно от сервера

- Linux с Docker и плагином Docker Compose (`docker compose version` должен отвечать).
- 1 CPU, 1 ГБ памяти, 10 ГБ диска — с запасом. Внешних сервисов и очередей нет.
- Свободный порт на `127.0.0.1` — по умолчанию 8000, меняется в `.env`.
  Наружу приложение ничего не слушает, портов 80 и 443 не занимает.
- Фронтовой веб-сервер площадки, который проксирует на этот порт, и запись в DNS.
- Место для резервных копий **за пределами этого сервера**.

Своего обратного прокси у приложения нет: оно висит на loopback, как обычный
сайт, и спокойно соседствует с другими на том же хосте. TLS, домен и сертификат —
на фронтовом веб-сервере, приложение об этом ничего не знает.

Что поднимется: два контейнера — `postgres:16-alpine` и приложение на
`python:3.12-slim` (FastAPI + uvicorn). Образ собирается на сервере
из `Dockerfile`, ничего скачивать из приватных реестров не нужно.

## Установка

```bash
git clone https://github.com/smirnoff0909/daily-reports.git /opt/daily-reports
cd /opt/daily-reports
git checkout stable          # ветка stable — рабочая версия

cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # в SECRET_KEY
```

Заполнить `.env`:

| Переменная | Значение |
| --- | --- |
| `APP_PORT` | порт на `127.0.0.1`, куда проксирует фронтовой веб-сервер. По умолчанию `8000`, смените, если занят |
| `SECRET_KEY` | сгенерированная строка сверху, никому не показывать |
| `POSTGRES_PASSWORD` | придумать длинный пароль |
| `POSTGRES_USER`, `POSTGRES_DB` | можно оставить `reports` |
| `APP_TIMEZONE` | `Europe/Moscow` — в этом поясе считается «сегодня» |
| `COOKIE_SECURE` | `true`, если пользователи открывают сайт по https. Именно по схеме у пользователя, а не по схеме до контейнера — до него всегда http. `false` только если сайт вообще без TLS |

Запуск:

```bash
docker compose up -d --build
docker compose ps
curl -s 127.0.0.1:8000/healthz     # ожидается {"status":"ok"}
```

Миграции базы применяются автоматически при старте контейнера приложения,
руками ничего накатывать не нужно.

## Фронтовой веб-сервер

Приложение отвечает на `127.0.0.1:8000` (или на том порте, что задан в `APP_PORT`).
Схема запроса:

```
браузер --https--> фронтовой веб-сервер --http--> 127.0.0.1:8000 --> приложение
```

Сертификат, домен и перенаправление с http на https — на фронтовом сервере,
как у любого другого сайта площадки. Пример для nginx:

```nginx
server {
    listen 443 ssl;
    server_name reports.company.ru;

    ssl_certificate     /etc/ssl/certs/reports.crt;
    ssl_certificate_key /etc/ssl/private/reports.key;

    client_max_body_size 2m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Отдельно про `COOKIE_SECURE=true`: флаг ставится по схеме, которую видит
пользователь, а не по схеме до контейнера — до него всегда http.
Заголовок `X-Forwarded-Proto` передавать полезно для порядка, но на работу
приложения он не влияет: переадресации внутри относительные (`/reports`,
`/login`), абсолютных адресов приложение не строит, а защищённость cookie
берётся из `.env`.

Статику приложение отдаёт само, отдельной раздачи файлов настраивать не нужно.

## Учётные записи

База поднимается пустой. Первым заводится руководитель, дальше он добавляет
людей сам через веб-интерфейс, раздел «Сотрудники».

```bash
docker compose exec app python -m scripts.manage_users add \
  --name "Немчинов Лев" --login nemchinov --role manager
```

Пароль спрашивается интерактивно и не остаётся в истории команд.
Другие команды скрипта: `passwd`, `disable`, `enable`, `list`.

## Резервные копии

`scripts/backup.sh` делает `pg_dump`, сжимает его и удаляет копии старше 30 дней.
В cron:

```
0 2 * * * cd /opt/daily-reports && ./scripts/backup.sh >> /var/log/daily-reports-backup.log 2>&1
```

Копии обязательно переносить за пределы сервера — иначе они умрут вместе с диском.

## Обновление версии

```bash
cd /opt/daily-reports
git pull
docker compose up -d --build
```

Миграции применятся при старте. Перед обновлением снять резервную копию.

## Обслуживание

```bash
docker compose logs -f app        # логи приложения
docker compose restart app        # перезапуск
docker compose down               # остановить всё (данные в томах сохраняются)
```

Данные лежат в docker-томе `db-data`. При `docker compose down` он не удаляется;
`down -v` его сотрёт вместе со всеми отчётами.

## Чего в приложении нет

Регистрации, восстановления пароля по почте, интеграций и фоновых задач.
Один процесс, одна база. Пароли — argon2, сессия в подписанной cookie.
